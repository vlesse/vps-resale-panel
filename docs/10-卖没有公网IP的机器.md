# 第 10 章　卖没有公网 IP 的机器（NAT VPS）

家里那台物理机、公司机柜里那台闲置服务器，性能往往比你在云上租的强得多，
但它们有个共同问题：**没有公网 IP，或者只有一个，分不出来**。

这一章讲怎么用一台便宜的公网机器当「入口」，把这些机器变成能卖的商品。
买家拿到的是一个**真实公网地址 + 一段端口**，机器上什么都不用装。

---

## 10.1 它是怎么工作的

```
买家 ─── 34.80.126.84:20000 ──┐
                              │  入口机器（有公网 IP，1 核 1G 就够）
                              │  面板在它上面写 iptables 端口映射
                              ▼
                        隧道（Tailscale / WireGuard）
                              │
                              ▼
                     你家的 Proxmox ── 私网 172.31.0.x ── 虚拟机
```

三方各司其职：

| 角色 | 干什么 | 要求 |
|------|--------|------|
| **入口机器** | 接客、转发 | 有公网 IP、能跑 iptables |
| **隧道** | 把入口和你的私网连起来 | 面板不管，你自己搭 |
| **你的机器** | 真正干活 | 完全不需要公网 IP |

**你家的路由器不用开任何端口**，也不需要固定 IP、不需要动态域名。
隧道是从你家主动连出去的。

---

## 10.2 买家能拿到什么

一台 NAT 机器交付时给的是：

| | 例子 |
|---|---|
| 地址 | `34.80.126.84` ← 真公网 IP |
| SSH 端口 | `20000` |
| 端口段 | `20001–20019`，TCP + UDP |
| 机器自己的地址 | `172.31.0.2`（私网，登进去看到的是这个） |

端口段是**原样转发**的：买家在机器上让服务监听 `20005`，
外面就用 `34.80.126.84:20005` 访问，不用换算，也不用记两套号码。

> **这一点一定要写进套餐说明。** NAT VPS 最常见的工单就是
> 「我 ssh 进去 `ip addr` 一看是 172.31 开头的，是不是给我假机器？」
> 面板的控制台里已经把两个地址都摆出来并解释了，但商品页上你也该写一句。

**段外的端口不通，包括 80 和 443。** 买家要跑网站，可以让它监听端口段里的某个端口，
或者用下面 10.11 的二级域名 —— 那个是直通 80 的。

---

## 10.3 准备入口机器

任何一台有公网 IP 的 Linux 都行，1 核 1G 足够 —— 它只转发，不干活。
可以和面板本身跑在同一台上。

**1. 开内核转发**

```bash
printf 'net.ipv4.ip_forward=1\nnet.ipv6.conf.all.forwarding=1\n' > /etc/sysctl.d/99-panel-nat.conf
sysctl -p /etc/sysctl.d/99-panel-nat.conf
```

**2. 确认它能路由到你的私网**

```bash
ip route show table all | grep 172.31
```

Tailscale 的子网路由不会出现在主路由表里，它在 `table 52`，所以要加 `table all`。
看不到就是隧道那边还没通，先解决它 —— 面板这边配得再对也没用。

**3. 云厂商的防火墙要放行端口段**

这一步最容易漏。iptables 规则写对了、隧道也通了，外面就是连不上，
十有八九是安全组没开。谷歌云是 VPC 防火墙，AWS 是安全组，
放行你打算分配的那一整段 TCP + UDP。

## 10.4 搭隧道（以 Tailscale 为例）

Tailscale 比手搓 WireGuard 省事得多：不用管密钥交换、不用管 NAT 穿透、
两边都在 NAT 后面也能直连。

**在你的 Proxmox 宿主机上：**

```bash
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up --advertise-routes=172.31.0.0/24 --accept-dns=false --hostname=pve-1
```

它会打印一个授权链接，浏览器打开点一下。

**然后一定要去管理台批准这条子网路由** ——
不批的话广播出去也不会生效，这一步最容易忘：

> [https://login.tailscale.com/admin/machines](https://login.tailscale.com/admin/machines)
> → 找到这台机器 → 「⋯」 → 「Edit route settings」 → 勾上 `172.31.0.0/24` → Save

**在入口机器上：**

```bash
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up --accept-routes
```

已经装过 Tailscale 的话，只要：

```bash
tailscale set --accept-routes=true
```

验证：

```bash
ping -c3 172.31.0.1        # 你的私网网关
ip route show table all | grep 172.31
```

## 10.5 在 Proxmox 上开一个私网网桥

虚拟机要待在一个独立网段里，不要和你家的局域网混在一起。

```bash
cp /etc/network/interfaces /root/interfaces.bak      # 先备份，这个文件改坏了机器就失联

cat >> /etc/network/interfaces <<'EOF'

auto vmbr1
iface vmbr1 inet static
    address 172.31.0.1/24
    bridge-ports none
    bridge-stp off
    bridge-fd 0
    post-up   iptables -t nat -A POSTROUTING -s 172.31.0.0/24 -o vmbr0 -j MASQUERADE
    post-down iptables -t nat -D POSTROUTING -s 172.31.0.0/24 -o vmbr0 -j MASQUERADE
EOF

ifup vmbr1        # 只启这一个网桥，不要 systemctl restart networking
```

> ⚠️ 用 `ifup vmbr1`，**不要**重启整个网络服务。远程操作时重启网络
> 有一定概率把你自己关在门外，而这台机器往往就在你够不着的地方。

`MASQUERADE` 那条是让虚拟机能上网（装软件、更新系统）。
买家进来的流量走的是另一条路，不靠它。

## 10.6 模板机的一个坑

**Proxmox 的 `ipconfig0` 只有在虚拟机里的 cloud-init 允许配置网络时才生效。**

很多现成的模板（包括不少一键脚本做出来的）里带着这两个东西：

```
/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg   ← 禁用了 cloud-init 配网
/etc/netplan/99-xxx.yaml                               ← 写死的静态配置
```

有这两个文件的话，克隆出来的虚拟机**会完全无视面板分配的地址**，
表现是：虚拟机能开机、能登控制台，但网卡是 DOWN 的，怎么都连不上，
而面板那边只会一直卡在「等待虚拟机拿到 IP」。

进模板机删掉它们：

```bash
rm -f /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
rm -f /etc/netplan/99-*.yaml
apt-get install -y qemu-guest-agent
systemctl enable qemu-guest-agent
cloud-init clean --logs --seed
rm -f /etc/ssh/ssh_host_*          # 不删的话所有虚拟机共用一份主机密钥
truncate -s0 /etc/machine-id
poweroff
```

关机后转换成模板。检查方法：克隆一台出来开机，
控制台里 `ls /etc/netplan/` 应该看到 `50-cloud-init.yaml`。

## 10.7 在面板里配 NAT 网关

后台 → 「**NAT 入口**」 → 「**+ 添加网关**」

| 字段 | 填什么 | 说明 |
|------|--------|------|
| 名称 | `香港入口` | 给自己看的 |
| 对外地址 | `34.80.126.84` | 买家看到、也是买家去连的 |
| 私网网段 | `172.31.0.0/24` | 要和套餐里的 `ipPool` 一致 |
| 面板连它的地址 | 留空 | 一般和对外地址一样 |
| SSH 端口 / 用户 | `22` / `root` | 面板要用它写 iptables |
| 密码或私钥 | | 建议用私钥 |
| 起始 / 结束端口 | `20000` / `39999` | |
| 每台机器分几个端口 | `20` | 第一个固定通到机器的 22 |

按这个填法，一台入口能带 **1000 台**机器。

加好之后点「**测试**」。它会连上去检查三件事：
内核转发开了没、有没有到私网的路由、iptables 在不在。
哪一项不过都会直接告诉你该去修哪里。

### 面板往网关上写了什么

只有两条**面板独占**的链：

```
PANEL-NAT （挂在 nat 表 PREROUTING 最前面）
PANEL-FWD （挂在 filter 表 FORWARD 最前面）
```

每次下发都是**整链重写**：清空这两条链，再把当前该有的规则全写一遍。
不做增量修改 —— 网关重启过、别人手工动过、上次下发到一半断了，
面板都无从知道现场长什么样，整链重写则不管现场如何一次对齐。

**Docker、Tailscale、以及你自己手写的规则一根都不会被碰到。**
入口机器上跑着别的服务（比如你原来的网站）完全没问题。

规则同时会写进 `/usr/local/sbin/panel-nat.sh`，
并装一个 `panel-nat.service` 开机自启 —— 网关重启后映射会自己回来。

## 10.8 建一个 NAT 套餐

按 [第 5 章](05-上架第一个套餐.md) 建套餐，平台选「自建 Proxmox VE」，
建机参数里比普通 Proxmox 套餐多两项：

```json
{
  "templateVmid": 9000,
  "storage": "local-lvm",
  "bridge": "vmbr1",
  "cores": 2,
  "memoryMb": 2048,

  "ipPool": "172.31.0.0/24",
  "gateway": "172.31.0.1",
  "nameserver": "8.8.8.8",
  "natGatewayId": 1
}
```

| 参数 | 作用 |
|------|------|
| `ipPool` | 面板从这个池子里给机器分私网地址 |
| `gateway` / `nameserver` | 写进 cloud-init，不靠 DHCP |
| `natGatewayId` | 用哪个入口对外。后台 NAT 入口页面上那个网关的 ID |

地址由**面板**分配、通过 cloud-init 静态写进去，不等虚拟机自己上报。
这样就不依赖 qemu-guest-agent，交付快，也不会卡在「等待拿到 IP」。

## 10.9 端口段是怎么分的

第一台机器拿 `20000–20019`，第二台 `20020–20039`，以此类推。
每段的第一个端口映射到机器的 `22`，其余原样转发。

退订销毁一台机器时，它的端口段会**还回池子**，下次优先被重新用上。
所以端口号不会一路往上涨到用完。

> 库存池模式的机器（`ssh` 驱动）退订时**不还**端口段 ——
> 它回池子里继续待命，面板还得靠这段端口连上去做清理和重装。

## 10.10 常见问题

| 现象 | 原因 | 怎么修 |
|------|------|--------|
| 后台点「测试」说「没有到 172.31.0.0/24 的路由」 | 隧道没通，或子网路由没批准 | 回 10.4，特别是管理台批准那一步 |
| 测试全过，但外面连不上分配的端口 | 云厂商防火墙没放行端口段 | 安全组 / VPC 防火墙放行整段 TCP + UDP |
| 连端口段里的端口秒断（Connection refused） | 机器上那个端口没有服务在听 | 正常现象，说明转发是通的 |
| 开通卡在「等待虚拟机拿到 IP」 | 模板里禁用了 cloud-init 配网 | 见 10.6 |
| 买家说 `ip addr` 看到的是内网地址 | 这是 NAT 的正常表现 | 控制台里已有说明，商品页也写一句 |
| 网关重启后映射全没了 | `panel-nat.service` 没起来 | `systemctl status panel-nat`，或后台点「重新下发」 |

## 10.11 送二级域名（直通机器的 80）

端口段解决了 SSH 和自定义服务，但**网站**是另一回事：
买家在 `34.80.126.84:20005` 上跑一个博客，链接又长又丑，还没有 HTTPS。

面板可以给每台机器送一个二级域名，直通它的 80：

```
https://m20020.nat.renrenyings.net  →  172.31.0.3:80
```

证书、续期、反代全在网关上做完，买家机器里什么都不用装 ——
起一个监听 80 的服务就能用。想换成自己的域名，CNAME 过来就行。

### 域名怎么取

`m` + 这台机器的 SSH 端口 + 你配的根域。用 SSH 端口做标签是因为
它本来就是唯一的，而且买家为了登录本来就要记住它，不用再多记一个号码。

### 一、DNS 加一条泛解析

```
*.nat.example.com    A    你的网关公网 IP
```

### 二、申请泛域名证书

泛域名证书**只能走 DNS 验证**，HTTP 验证签不出来。
下面以 Cloudflare 为例（换别家换插件名即可）：

```bash
apt install -y python3-certbot-dns-cloudflare

mkdir -p /root/.secrets
cat > /root/.secrets/cloudflare.ini <<'EOF'
dns_cloudflare_api_token = 你的令牌
EOF
chmod 600 /root/.secrets/cloudflare.ini

certbot certonly --dns-cloudflare \
  --dns-cloudflare-credentials /root/.secrets/cloudflare.ini \
  -d '*.nat.example.com' --agree-tos -m 你的邮箱 -n
```

> 令牌在 Cloudflare 后台「My Profile → API Tokens → Create Token」，
> 用 **Edit zone DNS** 模板，Zone Resources 只勾你这一个域名。
> 权限越小越好 —— 这个令牌只需要能改 DNS 记录。

证书续期是自动的，certbot 自己的定时任务会用同一个令牌再跑一遍。

### 三、装站点配置

仓库里的 `deploy/nginx-nat-web.conf` 就是现成的，改掉里面的域名，
放到 `/etc/nginx/sites-available/nat-web` 并软链到 `sites-enabled/`：

```bash
touch /etc/nginx/vps-panel-nat.map      # 面板会往里写，先建出来不然 nginx 起不来
nginx -t && systemctl reload nginx
```

它做两件事：

- 一个 `map`，把域名映射成机器的内网地址，内容 `include` 自
  `/etc/nginx/vps-panel-nat.map` —— **面板只写这一个文件**，
  站点配置本身不碰。让程序去改别人生产环境的 Nginx 主配置，
  写错一次整台机器上的网站全下线。
- 一个泛域名的 server 块，把请求转给映射出来的地址。
  映射里查不到就直接 404（机器已经退订，或者域名是瞎猜的）。

### 四、在面板里填上根域

后台 → 「NAT 入口」→ 改那个网关 → 「二级域名根域」填 `nat.example.com`，
保存后点一次「重新下发」。

面板每次下发端口映射时会顺带重写那个 map 文件，`nginx -t` 过了才 reload；
过不了就把文件原样退回去，**绝不会 reload 一个坏配置**。
域名这块失败也不会影响端口映射 —— 端口已经生效，机器是能用的。

## 10.12 和别人卖的 NAT 机器比

| | 常见的 NAT 卖家 | 这里 |
|---|---|---|
| 开通 | 人工，几小时到一天 | 付款后一分钟内自动交付 |
| 端口 | 人工分配，工单沟通 | 自动分段，控制台上写得清清楚楚 |
| 端口映射规则 | 卖家手写，容易漏、容易冲突 | 面板整链重写，永远和数据库一致 |
| 入口机器重启 | 映射经常丢，要发工单 | systemd 开机自动恢复 |
| 退订 | 端口段常年占着 | 自动回收 |
| UDP | 很多不给 | TCP + UDP 都给 |
| 重装 | 多半没有 | 真重装，而且落回原来的地址和端口段 |
| 建站 | 自己想办法，多半得另买域名和证书 | 送二级域名，HTTPS 现成的，直通 80 |
