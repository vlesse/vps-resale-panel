# 第 8 章　日常运营

平台跑起来之后，每天要看什么、遇到常见情况怎么处理。

---

## 8.1 每天花两分钟看这三样

打开后台首页（「**总览**」），从上往下：

### 1️⃣ 「疑似还在计费的残留实例」—— 最要紧

这个红色的框**平时不应该出现**。出现了说明有机器可能正在你的云账号上
按小时扣钱，而面板已经把它们当废弃了。

成因通常是：建机建到一半失败了，面板尝试自动销毁但也失败了
（比如当时云厂商在抽风、或者密钥刚好过期）。

**怎么处理：**

框里会列出「云端实例名」和可用区，比如 `m260827053922fa4848 @ asia-northeast1-a`。

1. 拿这个名字到对应云厂商的控制台里搜
2. **搜得到** → 点「**重试销毁**」，让面板再删一次。还是失败就在云控制台手动删掉，
   然后回来点「已确认清理」
3. **搜不到**（已经不存在了）→ 直接点「**已确认清理**」，从告警列表里消掉

> 这个列表非空的每一天，都可能在漏钱。**养成每天看一眼的习惯。**

### 2️⃣ 云账号连接告警

黄色框，写着「有 N 个云账号的连接测试没通过」。

出现这个的话，**那些账号下的所有套餐现在都开不出机器** ——
用户能下单、能付款，但开通会失败。

常见原因：

- 密钥在云厂商那边被删了或者过期了
- 云账号欠费被停了
- 服务账号的权限被改了

点「去处理」→ 到云账号页点「测试连接」看具体报错，
对照 [第 3 章](03-接入谷歌云.md) 或 [第 4 章](04-接入-AWS-Lightsail.md) 的报错表。

### 3️⃣ 最近订单里的「开通失败」

用户付了钱但机器没建出来。这是必须当天处理的，**用户的钱在你手上但没拿到货**。

到「订单」页，找到那笔，看「开通进度」列里的错误信息：

| 错误里出现 | 意思 | 怎么办 |
|-----------|------|--------|
| 谷歌云配额不够了 | 那个区域的 CPU 或 IP 配额用完了 | 去云控制台申请提额，或者换个区域再建一个套餐 |
| 谷歌云不认这份密钥 | 密钥失效 | 重新配云账号 |
| 服务账号权限不够 | 权限被改了 | 补权限 |
| 今天已经自动创建了 N 台，达到平台每日上限 | 你自己设的闸门顶到了 | 调大 `.env` 里的 `MAX_DAILY_PROVISION` |
| 你名下已经有 N 台机器，达到了上限 | 这个用户到上限了 | 到「用户」页给他单独提额 |
| 系统初始化脚本超过 3 分钟还没跑完 | 机器建出来了但初始化没完成 | 点「重试开通」；反复出现的话可能是镜像有问题，换个镜像 |

修好原因之后点「**重试开通**」，系统会从头重新建一台。
上一次失败的半成品已经在失败时自动回滚掉了，不会重复计费。

**实在建不出来的**，就在支付渠道那边给用户退款，然后到订单页把订单取消。

## 8.2 每周做的事

### 对一遍云厂商的机器数

面板知道的机器数应该和云厂商控制台里的对得上。

- 面板：后台 →「机器」，看「运行中」+「已关机」的数量
- 谷歌云：控制台 → Compute Engine → 虚拟机实例
- AWS：Lightsail 控制台 → 实例

**云厂商那边多出来的就是漏网的**，确认不是别的项目在用之后删掉。

**AWS 还要额外看一眼「静态 IP」标签页** —— 没绑在实例上的静态 IP 也是收费的。

### 对一遍账

后台订单页顶部显示各币种已收总额，和你支付服务商后台的流水对一下。

### 看一眼快到期的服务

后台 →「机器」，或者直接查数据库：

```bash
cd /opt/panel
docker compose exec mysql mysql -uvps -p vps_resale -e \
  "SELECT service_no, expire_at, DATEDIFF(expire_at, NOW()) AS days_left
   FROM services WHERE status='active' AND expire_at < DATE_ADD(NOW(), INTERVAL 7 DAY);"
```

（会让你输 `.env` 里的 `MYSQL_PASSWORD`）

快到期的可以主动提醒用户续费。

## 8.3 系统自动在做的事

这些不用你管，知道有这回事就行：

| 什么时候 | 做什么 |
|---------|-------|
| 每 5 分钟 | 取消超时未付款的订单，把被占的库存机放回池子 |
| 每小时 | 扫描到期的服务，关机并标记为「已到期」 |
| 建机失败时 | 自动销毁半成品实例，避免留下计费的僵尸机器 |
| 建机失败后 | 自动重试最多 3 次，指数退避 |

**到期是「挂起」不是「销毁」。** 机器会被关机但数据还在，
用户续费之后能恢复。真正的销毁要你到后台手动做 —— 
用户很可能只是忘了续费，直接删数据是没法解释的。

## 8.4 常见运营场景

### 用户说「机器连不上」

1. 到后台 →「机器」找到他的机器，点「测连接」
2. 面板能连上 → 多半是用户那边的问题（本地网络、密码抄错、SSH 客户端配置）
3. 面板也连不上 → 到云厂商控制台看实例状态，可能是欠费被停或者机器挂了

### 用户忘了密码

让他自己到控制台点「重置密码」就行，不用你操作。
重置走的是面板自带的密钥，用户改过密码也不影响。

### 用户要退款

1. 在支付渠道那边执行退款
2. 后台 →「机器」找到那台，销毁掉（要抄机器编号确认）
3. 后台 →「订单」把订单状态改掉

### 想给某个用户多买几台的权限

后台 →「用户」→ 找到他 → 点「改上限」，填一个数字。
填 0 表示用 `.env` 里的全局默认值。

### 想停掉某个捣乱的用户

后台 →「用户」→ 点「停用」。他手上的令牌会**立刻失效**
（每次请求都会回数据库查状态），机器还在但登不进面板了。

### 调整防刷单闸门

```bash
cd /opt/panel && nano .env
```

改这三个值，然后 `docker compose up -d` 生效：

```ini
MAX_ACTIVE_SERVICES_PER_USER=5    # 单用户同时持有上限
MAX_DAILY_PROVISION=50            # 全平台每日建机上限
ORDER_EXPIRE_MINUTES=30           # 未付款订单超时分钟数
```

单个云账号的每日配额在后台「云账号」页里单独设。

## 8.5 备份

**数据库要定期备份。** 里面有你所有的用户、订单、以及每台机器的加密凭据。

### 手动备份一次

```bash
cd /opt/panel
docker compose exec -T mysql mysqldump -uroot -p"$(grep '^MYSQL_ROOT_PASSWORD=' .env | cut -d= -f2)" \
  --single-transaction vps_resale > backup-$(date +%Y%m%d).sql
```

### 设成每天自动备份

```bash
mkdir -p /opt/panel-backups
cat > /etc/cron.daily/panel-backup <<'EOF'
#!/bin/bash
cd /opt/panel
PW=$(grep '^MYSQL_ROOT_PASSWORD=' .env | cut -d= -f2)
docker compose exec -T mysql mysqldump -uroot -p"$PW" --single-transaction vps_resale \
  | gzip > /opt/panel-backups/vps_resale-$(date +%Y%m%d).sql.gz
# 只留最近 14 天
find /opt/panel-backups -name '*.sql.gz' -mtime +14 -delete
EOF
chmod +x /etc/cron.daily/panel-backup
```

### ⚠️ 光备份数据库是不够的

数据库里的凭据是**加密**的，解密要靠 `.env` 里的 `CREDENTIALS_SECRET`。

**这两样必须一起备份，而且要分开存放**：

- 数据库备份文件
- `CREDENTIALS_SECRET` 的值（存密码管理器或者纸上）

只有数据库没有密钥的话，恢复出来所有云账号和机器密码都是解不开的乱码，
等于所有卖出去的机器都失控了。

## 8.6 升级面板

```bash
cd /opt/panel
git pull
docker compose up -d --build
```

数据库表结构会在后端启动时自动同步，不用你做迁移。

**升级前先备份一次数据库。**

---

## 8.7 换服务器

1. 在新服务器上做完 [第 1 章](01-你需要准备什么.md) 和 [第 2 章](02-把面板装起来.md) 的第 2.2 步（下载代码）
2. 把老服务器的 `.env` 整个复制过去（**`CREDENTIALS_SECRET` 必须一模一样**）
3. 把数据库备份恢复到新机器
4. `docker compose up -d`
5. 改域名解析指向新 IP
6. 等证书自动申请好，确认能访问之后再关掉老服务器
