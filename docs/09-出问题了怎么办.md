# 第 9 章　出问题了怎么办

按现象查。找到你遇到的那一行，照着做。

---

## 先学会看日志

出任何问题，第一件事都是看日志。所有命令都要先进面板目录：

```bash
cd /opt/panel
```

| 想看什么 | 命令 |
|---------|------|
| 各服务活着没有 | `docker compose ps` |
| 后端在干什么 | `docker compose logs api --tail 100` |
| 实时盯着后端 | `docker compose logs -f api`（Ctrl+C 退出） |
| HTTPS 证书的问题 | `docker compose logs caddy --tail 50` |
| 数据库的问题 | `docker compose logs mysql --tail 50` |
| 前端的问题 | `docker compose logs web --tail 50` |
| 只看错误 | `docker compose logs api --tail 200 \| grep -i error` |

**想看更详细的建机过程**，把 `.env` 里的 `LOG_LEVEL` 改成 `debug`，
然后 `docker compose up -d`。排查完记得改回 `log`，
不然日志会涨得很快。

## A. 网站打不开

### A1. 浏览器一直转圈 / 连接超时

```bash
# 1. 服务都活着吗
cd /opt/panel && docker compose ps
```

不是全部 `Up` → 跳到 [B 节](#b-服务起不来)。

```bash
# 2. 域名解析对吗（在你自己电脑上执行）
nslookup panel.你的域名.com
```

IP 不是你服务器的 → 回 [第 1 章](01-你需要准备什么.md) 重做解析，等 10 分钟。

**3. 端口被防火墙挡了？** 到服务商后台的「安全组 / 防火墙」里确认
80 和 443 都放行了。国内服务器还要确认域名**已经备案**，否则 80 口是封的。

### A2. 浏览器说「不安全」或证书错误

```bash
docker compose logs caddy --tail 40
```

| 日志里出现 | 怎么办 |
|-----------|--------|
| `no such host` / `DNS problem` | 域名没解析对，回 A1 第 2 步 |
| `connection refused` on port 80 | 放行 80 端口 |
| `too many certificates already issued` | 触发了 Let's Encrypt 频率限制（同一域名一周 5 次）。**等一小时**再试。急着测试的话编辑 `deploy/Caddyfile` 把 `acme_ca` 那行的注释去掉用测试证书 |
| `timeout` | Let's Encrypt 访问不到你的服务器，检查 80 端口和防火墙 |

### A3. 打开了但是白屏 / 一直「正在读取…」

后端挂了或者连不上数据库：

```bash
curl -s https://panel.你的域名.com/api/health
```

正常应该返回 `{"status":"ok","database":"ok",...}`。

- 返回 `"database":"fail..."` → 数据库有问题，看 [B3](#b3-mysql-起不来)
- 完全没返回 → 后端挂了，看 [B2](#b2-api-起不来)

## B. 服务起不来

### B1. 怎么定位

```bash
cd /opt/panel && docker compose ps
```

哪个不是 `Up` 就看哪个的日志：`docker compose logs <服务名> --tail 50`

### B2. api 起不来

| 日志里出现 | 意思 | 怎么办 |
|-----------|------|--------|
| `CREDENTIALS_SECRET 至少要 32 个字符` | 那个值填短了或空着 | `nano .env` 补上，`docker compose up -d` |
| `.env 里没有配 CREDENTIALS_SECRET` | 同上 | 同上 |
| `Can't connect to MySQL` / `ECONNREFUSED` | 数据库还没起来 | 等一分钟。一直这样看 B3 |
| `Access denied for user 'vps'` | `.env` 改过数据库密码，但数据库里还是老密码 | 见 [B4](#b4-改过数据库密码之后连不上了) |
| `EADDRINUSE` | 端口被占（容器里不该出现） | `docker compose down && docker compose up -d` |
| `Table 'xxx' doesn't exist` | 表没建出来 | `docker compose restart api`，启动时会自动同步表结构 |

### B3. mysql 起不来

```bash
docker compose logs mysql --tail 50
```

| 现象 | 怎么办 |
|------|--------|
| 反复重启 | 多半是内存不够。`free -m` 看一下，剩余不到 300 MB 的话加内存或者加 swap（见下） |
| `Access denied for root` | `.env` 的 `MYSQL_ROOT_PASSWORD` 和数据卷里存的对不上，见 B4 |

**加 swap**（内存不够时的临时办法）：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### B4. 改过数据库密码之后连不上了

MySQL 的密码是在**第一次启动时**写进数据卷的。之后改 `.env` 里的密码，
容器里的密码不会跟着变，就对不上了。

**还没有正式数据的话**，最简单是全部推倒重来（⚠️ 会删掉所有数据）：

```bash
cd /opt/panel
docker compose down -v
docker compose up -d
```

**已经有数据了**，就把 `.env` 改回原来的密码。忘了原密码的话，
进容器里改 MySQL 侧的密码来匹配 `.env`：

```bash
docker compose exec mysql mysql -uroot -p
# 输入旧的 root 密码，然后：
# ALTER USER 'vps'@'%' IDENTIFIED BY '新密码';
# FLUSH PRIVILEGES;
```

## C. 建机失败

### C1. 先看错误信息

后台 →「订单」，找到那笔，看「开通进度」那一列的红字。
或者用户自己在控制台页面上也能看到失败原因。

### C2. 谷歌云的错误

| 提示 | 意思 | 怎么办 |
|------|------|--------|
| 谷歌云不认这份密钥 | 密钥被删了 / 粘贴不完整 / 属于别的项目 | 重新下载 JSON，到「云账号」重填 |
| 密钥签名校验没过 | JSON 被编辑器改动过 | 用**记事本**打开原始文件重新复制 |
| 服务账号权限不够 | 角色没给够 | IAM 里加「Compute 实例管理员 (v1)」和「服务账号用户」 |
| 谷歌云配额不够了 | 那个区域的 CPU / IP 配额满了 | 控制台 → IAM 和管理 → 配额，申请提额；或换区域 |
| 这个项目还没启用 Compute Engine API | API 没开 | 控制台 → API 和服务 → 库 → 启用 |
| 这个项目没有绑定结算账号 | 没绑卡 | 去绑 |
| 同名实例已经存在 | 上次失败留下的残留 | 到谷歌云控制台删掉那个实例，再点「重试开通」 |
| 找不到对应资源 | 可用区 / 机型 / 镜像名写错 | 对照 [第 3 章](03-接入谷歌云.md) 的表检查套餐参数 |

### C3. AWS 的错误

| 提示 | 怎么办 |
|------|--------|
| AWS 密钥无效 | 到 IAM 确认密钥还在且是启用状态 |
| AWS 权限不够 | 给 IAM 用户附加 `AmazonLightsailFullAccess` |
| AWS 说参数不对 | 可用区 / bundleId / blueprintId 在这个区域不存在，对照 [第 4 章](04-接入-AWS-Lightsail.md) |
| AWS 账号还在初始化中 | 新账号，等几分钟 |

### C4. 通用的错误

| 提示 | 怎么办 |
|------|--------|
| 今天已经自动创建了 N 台，达到平台每日上限 | 调大 `.env` 的 `MAX_DAILY_PROVISION` |
| 你名下已经有 N 台机器，达到了上限 | 后台「用户」页给这个用户单独提额 |
| 云账号「xxx」今日建机数已达上限 | 后台「云账号」页调大那个账号的每日配额 |
| 这个套餐当前没有可用库存 | 库存池模式，没有「待售」状态的机器了，去补货 |
| 系统初始化脚本超过 3 分钟还没跑完 | 机器建出来了但初始化没完成。点「重试开通」；反复出现换个系统镜像 |
| 等了 240 秒还是连不上 SSH | 机器起来了但 22 端口不通。检查云厂商的防火墙规则（谷歌云的 VPC 防火墙要放行 22） |

### C5. 修好之后

到订单页点「**重试开通**」。系统会从头重新建一台，
上一次的半成品已经在失败时自动销毁了。

## D. 收款相关

### D1. 用户付了钱但订单还是「待付款」

**九成是回调地址没配对。** 支付成功后网关要主动通知你的面板，
这个地址要填在网关的商户后台里：

```
https://panel.你的域名.com/api/payments/jeepay/notify
```

**检查清单：**

1. 网关商户后台里的回调地址填了吗？拼写对吗？
2. `.env` 里的 `PANEL_DOMAIN` 对吗？
   ```bash
   cd /opt/panel && grep PANEL_DOMAIN .env
   ```
3. 这个地址公网能访问吗？在**别的机器上**试：
   ```bash
   curl -X POST https://panel.你的域名.com/api/payments/jeepay/notify
   ```
   返回 `fail` 是正常的（因为没带参数），说明地址通了。
   返回 404 或者连不上就是有问题。
4. 后端日志里有没有收到通知：
   ```bash
   docker compose logs api --tail 200 | grep -i jeepay
   ```
   看到「收到 Jeepay 通知」说明通知到了，往下看错误；
   什么都没有说明通知根本没发过来。

**应急处理**：后台 →「订单」→「标记已付」，手工放行这一单。
走的是和自动回调完全同一条路径，用户不受影响。

### D2. 日志里有「验签失败」

支付网关发来的通知签名对不上。原因：

- 面板里配的 `appSecret` 和网关那边不一致（最常见，通常是复制时带了空格）
- 网关那边换过密钥但面板没同步

到后台「支付」页把凭据重填一遍，点「测试」确认通过。

### D3. 用户重复付款了

面板的「标记已付」是**幂等**的 —— 同一笔订单处理过之后再收到通知会直接跳过，
不会给他建出第二台机器。多付的钱需要你在支付渠道那边退。

## E. 用户的机器出问题

### E1. 用户说连不上机器

1. 后台 →「机器」找到那台，点「**测连接**」
2. **面板能连上** → 用户那边的问题：本地网络、密码抄错、SSH 客户端配置。
   让他到控制台点「重置密码」拿一个新的
3. **面板也连不上** → 到云厂商控制台看实例状态：
   - 实例不在了 → 可能被误删，需要重新开通
   - 实例是 stopped → 在面板上点「开机」
   - 实例是 running 但连不上 → 云厂商防火墙可能被改了，检查 22 端口

### E2. 控制台上所有数据都是「—」

机器关机了，或者面板连不上它。看机器名右边那排状态点，
「电源」那个是灰的就说明处于关机状态，点「开机」。

如果读数下面出现一行琥珀色的「这次没连上（……），下面是上次的读数」，
说明机器还在、只是这一次探测失败了 —— 点「刷新状态」再试一次；
一直失败就按上面 E1 的办法查连通性。

### E3. 用户点了重装但没反应

重装是异步的，要一到三分钟。页面上应该有进度条。

进度条卡住不动超过 5 分钟：

```bash
docker compose logs api --tail 100 | grep -i rebuild
```

看具体卡在哪一步。

### E4. 「这台机器没有带外管理，关机之后没法远程开机」

这是**库存池模式**（自有机器）的固有限制，不是故障。
普通 VPS 没有带外管理，面板的关机是 SSH 进去执行 `poweroff`，
关掉之后就连不上了。

要到你的上游服务商控制台去手动开机。

想避免这个问题就用 Proxmox（有虚拟化层，开关机走 API），
见 [第 7 章](07-卖自己的机器.md)。

## F. 后台页面数据是空的

| 现象 | 原因 |
|------|------|
| 所有页面都空，导航栏也不显示用户名 | 登录过期了，退出重新登录 |
| 某一页显示红色错误条 | 照着错误信息查 |
| 页面能打开但完全没反应 | 浏览器缓存了旧版本，Ctrl+F5 强制刷新 |

## G. 实在查不出来

### 收集信息

```bash
cd /opt/panel
echo "=== 服务状态 ==="; docker compose ps
echo "=== 健康检查 ==="; curl -s http://127.0.0.1:3000/api/health
echo "=== 后端最近错误 ==="; docker compose logs api --tail 100 | grep -iE "error|failed" | tail -20
echo "=== 磁盘 ==="; df -h /
echo "=== 内存 ==="; free -m
```

### 常被忽略的两个原因

**磁盘满了。** `df -h /` 显示 100% 的话什么都会坏。
清理 Docker 的旧镜像：

```bash
docker system prune -a -f
```

**内存不够。** `free -m` 剩余不到 200 MB 的话 MySQL 会被系统杀掉。
加 swap（见 B3）或者升级服务器配置。

### 完全重来（⚠️ 会删掉所有数据）

```bash
cd /opt/panel
docker compose down -v
docker compose up -d
```

**做之前先备份**，见 [第 8 章 8.5](08-日常运营.md#85-备份)。
