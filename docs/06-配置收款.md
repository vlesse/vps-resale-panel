# 第 6 章　配置收款

这一章结束时，用户能真的付钱给你，付完系统自动开通机器。
最后还会带你完整走一遍下单到交付的演练。

---

## 6.1 先选一条路

面板内置五种收款方式，按「多久能开张」排：

| 方式 | 多久能用 | 要申请什么 | 自动到账 |
|------|---------|-----------|---------|
| **线下转账** | 10 分钟 | 什么都不用 | ❌ 你手工点确认 |
| **USDT（TRC20）** | 10 分钟 | 只要一个钱包地址 | ✅ |
| **易支付** | 1 到 3 天 | 找服务商开商户 | ✅ |
| **Jeepay** | 几天 | 自己部署或找服务商 | ✅ |
| **账户余额** | 加一下就有 | —— | ✅ 从余额扣 |

**建议：先开「线下转账」把生意跑起来，同时去申请易支付。**
收境外客户或者不想过资质审核的，USDT 是今天就能用的自动收款方式。

「账户余额」是另一回事：它不是一种收款渠道，而是让用户**先充值再消费**。
充值本身还是走上面那几种。加了它之后结算页才会出现「余额支付」，
老客户下单不用每次跳支付，一秒成交。见 [6.7](#67-账户余额先充值再消费)。

---

## 6.2 线下转账（最快开张）

后台 → 「**支付**」 → 「**+ 线下转账**」

| 字段 | 填什么 |
|------|--------|
| 通道代码 | `manual` |
| 显示名 | `银行转账` 或 `支付宝转账` |
| 给用户的说明 | 见下 |

「给用户的说明」这一栏会原样显示在结算页上，把付款方式和联系方式写清楚：

```
请转账到以下账号，转账后把订单号发给客服，我们确认后立刻为你开通。

支付宝：13800138000（张三）
微信：your-wechat-id
备注请填订单号

客服微信：your-service-wechat
工作时间：每天 9:00 - 22:00
```

点「添加并测试」。线下通道不需要测试，会直接通过。

## 6.3 易支付（推荐的自动收款方式）

「易支付」不是某一家公司，是国内被广泛克隆的**一套接口规范**。
各家服务商域名不同，接口长得一模一样，所以面板这一个驱动能对接任意一家。

### 你需要从服务商拿到三个值

| 值 | 长什么样 | 说明 |
|----|---------|------|
| 网关地址 | `https://pay.example.com` | **填到域名为止**，不要带 `/submit.php` |
| 商户 ID（PID） | `1001` | 一串数字 |
| 商户密钥（KEY） | 一长串 | **前后不要带空格** |

### 填进面板

后台 → 「**支付**」 → 「**+ 易支付**」

「支付方式」那一栏填 `alipay`（支付宝）、`wxpay`（微信）、
`qqpay`（QQ 钱包）或 `bank`（网银）。想同时提供支付宝和微信，
就加**两个通道**，代码分别叫 `epay_alipay` 和 `epay_wxpay`。

点「添加并测试」，面板会去查一次商户信息，当场告诉你 PID 和 KEY 对不对，
顺带把你的账户余额和支持的支付方式显示出来。

### 回调地址

不用你填，面板自动用 `.env` 里的 `PUBLIC_BASE_URL` 拼成：

```
https://你的域名/api/payments/epay/notify
```

**这个地址必须公网可达**，服务商是从他们自己的服务器发过来的。
`PUBLIC_BASE_URL` 填错的话，用户付了钱订单不会变成已支付。

### 几个容易踩的

| 现象 | 原因 |
|------|------|
| 一直报「签名错误」 | 商户密钥复制时多带了空格；或者用了别家网关的密钥 |
| 报「金额错误」 | 易支付的金额单位是**元**（两位小数），不是分。面板已经处理，自己改代码时注意 |
| 付款页打不开 | 有些服务商没开 `mapi.php`。面板会自动退回 `submit.php` 页面跳转，不用管 |
| 付了钱订单还是未支付 | 回调没通。看后端日志有没有「收到 epay 通知」，没有就是 `PUBLIC_BASE_URL` 或防火墙的问题 |

## 6.4 USDT（TRC20）

不需要商户账号，不需要资质，钱直接进你自己的钱包。
适合收境外客户，也适合不想碰第三方支付的人。

### 怎么配

后台 → 「**支付**」 → 「**+ USDT（TRC20）**」

| 字段 | 填什么 |
|------|--------|
| 收款地址 | 你钱包的 TRC20 地址，**T 开头 34 位** |
| TronGrid API Key | 选填。不填也能用，查询频繁时会被限流。[trongrid.io](https://www.trongrid.io) 免费申请 |
| 汇率 | 1 USDT 折多少人民币，比如 `7.25` |

> ⚠️ **别填 `0x` 开头的地址。** 那是以太坊（ERC20）的，链不一样，
> 用户按 TRC20 转过去的币会永远卡在半路。面板会拦住这种地址，但你自己心里要有数。

**面板不碰你的私钥**，只知道收款地址（那本来就是公开信息）。
提币是你自己在钱包或交易所里做的事。存了私钥的面板就是个热钱包，
一次 SQL 注入等于把钱包端走。

### 它是怎么认单的

链上转账**带不了订单号** —— 转过来的只是一笔金额，没有任何字段能塞进我们的单号。
所以面板用的是行业通行做法：**金额唯一**。

给每笔待付款分配一个此刻没人在用的精确金额（在原价上加不到 0.01 USDT 的随机尾数），
盯着链上，看到一笔正好这个数的转入就认定是它。

由此带来两件事：

- 用户**必须转那个精确金额**，页面上会用红字强调。转错数额要人工处理。
- 待付款有 30 分钟超时（`USDT_EXPIRE_MINUTES` 可改）。超时后那个金额被释放，
  给下一位用。挂着不付的单太多会占满可用金额。

面板每分钟扫一次链（只在真有人等付款时才扫，没人等就不请求，免得白撞限流）。
到账后页面自动更新，通常一到三分钟。

### 汇率什么时候生效

改汇率只影响**新发起**的付款。已经在等待的那些金额不会变 ——
用户看着一个数去转账，我们中途改成另一个数，那笔钱就永远对不上了。

## 6.5 Jeepay 聚合支付

Jeepay 是一个开源的聚合支付网关。你（或你的服务商）部署一套，
它对接下游各种支付方式，面板只跟它说话。

> 没有自建 Jeepay 的话跳过这一节，用上面的易支付就行 —— 对接成本低得多。

### 你需要从服务商拿到四个值

| 值 | 长什么样 | 说明 |
|----|---------|------|
| 网关地址 | `https://pay.example.com` | **填到域名为止**，不要带 `/api/pay` 这样的路径 |
| 商户号 mchNo | `M1234567890` | |
| 应用 ID appId | `65a3f...` | |
| 应用密钥 appSecret | 一长串 | **前后不要带空格** |
| 支付方式码 wayCode | `ALI_QR` | 支付宝扫码；微信是 `WX_NATIVE` |

### 填进面板

后台 → 「**支付**」 → 「**+ Jeepay**」，把上面五个值填进去。

「给用户的说明」写一句「支持支付宝、微信扫码」之类的就行。

点「**添加并测试**」。面板会真的去调一次网关，当场告诉你通不通。

### 还要在服务商那边配回调地址

**这一步最容易漏，漏了的结果是：用户付了钱，但订单一直显示「待付款」。**

支付成功之后，Jeepay 需要主动通知你的面板。这个通知地址要填在
Jeepay 的商户后台里：

```
https://panel.你的域名.com/api/payments/jeepay/notify
```

> 这个地址必须**公网能访问**。Jeepay 是从它自己的服务器发过来的，
> 不是从用户浏览器发的，所以内网地址、`localhost` 都不行。

面板这边的地址是根据 `.env` 里的 `PUBLIC_BASE_URL` 拼出来的。
如果你发现回调收不到，先确认这个值填对了：

```bash
cd /opt/panel && grep PANEL_DOMAIN .env
```

### 报错对照

| 提示 | 原因 |
|------|------|
| 网关能连上，但签名不通过 | 商户号 / 应用 ID / 应用密钥有一个抄错了，或者密钥前后带了空格 |
| 连不上支付网关 | 网关地址写错，或者对方服务没开 |
| 支付网关返回 404 | 网关地址带了多余的路径，只填到域名 |
| 支付网关说金额有问题 | 金额单位是「分」不是「元」，这个面板已经处理好了，出现说明服务商那边配置特殊 |

## 6.5b 收款码收的不是人民币怎么办

面板按人民币标价，但收款码不一定收人民币 —— 柬埔寨 ABA 的 KHQR 收的是**瑞尔**。
这时顾客会遇到一个面板不说他就一定会做错的事：**自己在手机上输金额**。

先确认你的码是哪种。把付款页上「二维码内容」那一长串抄出来，看开头：

```
00020101 0211 30510016abaakhppxxx@abaa...5303116...
        ^^^^                              ^^^
```

- `01` 后面是 `11` → **静态码，里面不带金额**，顾客要自己输
- `01` 后面是 `12` → 动态码，金额已经在码里，扫完直接付
- `53` 后面三位是币种：`116` = 瑞尔，`840` = 美元，`156` = 人民币

静态码 + 币种不是人民币，就必须开这个功能，否则你收到的钱一定是错的。

### 怎么开

后台 → 「**支付通道**」 → 那个通道的「**编辑**」：

| 字段 | 填什么 |
|------|--------|
| 顾客实付币种 | `KHR`（三个字母的币种代码） |
| 手工汇率 | 一般**留空**。留空就每天自动取当日汇率 |

留空的话面板每天凌晨三点去拉一次汇率（两个免费源，一个挂了用另一个），
付款页上会写「按 X 月 X 日汇率 1 人民币 ≈ 602.77 瑞尔 折算」。
拉不到就用上一次的值，并标注「参考汇率」—— **汇率取不到绝不会挡住付款**。

跟收单行谈了固定汇率的（ABA 常年 4100 KHR/USD 这种），把那个数填进「手工汇率」，
填了就不再查实时汇率。

### 开了之后用户看到什么

充值页和结算页上，选中通道后立刻出现一块高亮，用页面上最大的字号写着
**「扫码后请手动输入这个金额：30,139 瑞尔」**，旁边一个复制按钮。

折算一律**向上取整**到该币种的最小单位（瑞尔取到 1 瑞尔，美元取到 1 美分）。
最多多收一个最小单位，但永远不会少收 —— 少收的那部分是从你口袋里出的。

> 只影响给顾客看的数字，报给支付网关的金额和币种一个字都不改。
> 静态码本来就没法让网关校验金额，改它没有意义，只会给对账添乱。

## 6.6 完整演练一遍

**这一步非常重要。** 只有真的走一遍才知道整条链路通不通。

### 第 1 步：用测试账号注册

用**无痕窗口**（Ctrl+Shift+N）打开你的网站，注册一个新账号，
比如 `test@你的域名.com`。

> 用无痕窗口是为了不影响你已经登录的管理员会话。

### 第 2 步：下单

首页选你上架的那个套餐，点「立即开通」。

应该跳到结算页，显示订单号、金额、还有一个倒计时。

### 第 3 步：付款

**如果配了 Jeepay**：选支付方式，点「去支付」，用真实小额支付试一次
（可以临时把套餐价格改成 1 元来测）。

**如果只配了线下转账**：不用真转账，直接用下面的后台补单跳过。

### 第 4 步：后台标记已付

回到你的管理员窗口，后台 → 「**订单**」，找到刚才那笔（状态是「待付款」），
点「**标记已付**」。

> 「标记已付」走的和支付回调**完全同一条代码路径**，
> 所以手工补的单和自动收款的单行为完全一致，测试结果是可信的。

### 第 5 步：看着机器被建出来

回到测试账号那个窗口，结算页会自动刷新，你会看到：

```
付款已到账，正在开通机器
[████████░░░░░░░░] 42%
正在等待实例启动
```

进度条会一路走：

| 进度 | 在做什么 |
|------|---------|
| 3% | 检查配额 |
| 12% | 向云厂商提交建机请求 |
| 28% | 云厂商正在创建实例 |
| 42% | 等待实例启动 |
| 52% | 分配并绑定静态公网 IP |
| 58% | 配置防火墙端口 |
| 68% | 等待系统启动并开放 SSH |
| 86% | 等待系统初始化完成 |
| 100% | 交付完成 |

**整个过程 60 到 120 秒。**

### 第 6 步：验证机器真的能用

开通完成后点「进入控制台看登录信息」，你会看到 IP、端口、用户名、密码。

点「**复制 SSH 命令**」，到你自己电脑的终端里粘贴执行，输入页面上的密码。
能登进去就说明**整条链路完全打通了**。

进去之后可以验证一下初始化脚本跑对了：

```bash
cat /var/lib/vps-panel-bootstrap.done      # 应该输出一个时间戳
sysctl net.ipv4.tcp_congestion_control     # 应该显示 bbr
```

### 第 7 步：试一遍控制台的按钮

在面板的控制台页面上依次点：

- **重启** —— 几秒后 SSH 会断开，一分钟后能重连
- **重置密码** —— 会给你一个新密码，用新密码能登进去
- **关机** —— 机器停止，控制台上电源灯灭掉
- **开机** —— 机器恢复

### 第 8 步：清理

测试完把这台机器销毁掉，别让它一直计费：

后台 → 「**订单**」找到这笔，或者后台 → 「**机器**」找到这台，
把它销毁。销毁时要求你把机器编号原样抄一遍，这是防误触的。

---

## 到这一步你应该看到什么

- 结算页上能看到支付方式
- 下单 → 标记已付 → 进度条走完 → 拿到 IP 和密码
- 用那个 IP 和密码**真的能 SSH 登进去**
- 控制台上的重启、改密、关机、开机都有效
- 后台订单列表里那笔订单状态是「已完成」

**这七条都对了，你的平台就可以正式开张了。**

## 6.7 账户余额：先充值再消费

老客户每次下单都跳一次支付很烦，还每次都要付手续费。
余额把这件事变成：**充一次，用很多次**。

### 打开它

后台 → 「**支付**」 → 「**+ 账户余额**」，什么都不用填。

加完之后：

- 用户菜单里出现「**余额**」页，能充值、能看流水
- 结算页多一个「**余额支付**」选项，点了当场扣款、当场开通，不跳转

充值本身走你配的其它通道（线下转账 / 易支付 / USDT），
「余额支付」不会出现在充值页上 —— 拿余额充余额没有意义。

### 账都记在哪

每一次加减都会在 `wallet_txs` 里留一条流水，**只增不改不删**，
并且记着「这笔之后余额是多少」。用户在「余额」页能看到全部流水。

想核对的话，拿最后一条流水的余额跟 `users.balance_cents` 比一下，
**对不上就是有 bug**，不是「差一点点没关系」。

### 手工加减

后台 → 「**用户**」 → 那一行的「**调余额**」。填元（可以是负数），
然后**必须写原因** —— 事后对账全靠这一行字，所以面板不允许留空。

补偿、退款、纠错都走这里。

### 单币种

余额只有一个币种（默认人民币，`WALLET_CURRENCY` 可改）。
用户如果把价格切成美元下单，结算页上「余额支付」会明确告诉他
「账户余额是人民币账户，请切回人民币或换个支付方式」。

这是故意的：多币种钱包要么得存一套会漂移的汇率（账对不平），
要么得给每个币种各开一个余额（用户会问「为什么我有 100 块却买不了 10 美元的机器」）。
明确拒绝，是这几种做法里唯一不会悄悄算错钱的。

## 6.7b 通道的顺序很要紧

付款页默认选中**排序数字最小**的那个通道，而且会跳过「线下转账」。

跳过是有原因的：线下转账不出二维码也不自动到账，用户点完付款只看到
一句「转账后联系客服」，很容易以为付款功能坏了 —— 这个坑真踩过。

所以：

- 把能当场付掉的通道（扫码、易支付、USDT）的排序设成 0
- 线下转账排到最后
- 「给用户的说明」里**一定要写真实的收款账号**。写着 `xxx` 的话，
  用户看到的就是 `xxx`，他不知道该往哪转钱

排序和说明都在「支付通道」→「编辑」里改，不用删了重建。

## 6.8 收款之后

**每天看一眼后台订单页**，重点看两种：

- 状态是「**开通失败**」的：用户付了钱但机器没建出来。
  点「重试开通」再试一次；反复失败就看错误信息，多半是云账号配额或权限问题。
- 状态卡在「**开通中**」超过 10 分钟的：任务可能卡住了，也点「重试开通」。

**对账**：后台订单页顶部会显示各币种已收总额。
和你支付服务商后台的流水对一下，差额就是需要排查的。
