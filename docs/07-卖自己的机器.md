# 第 7 章　卖自己的机器

前面几章讲的是「用户下单后去云厂商现建一台」。这一章讲另一种：
**你手上已经有的机器**怎么放进来卖。

比如你从别家囤了几台便宜的 VPS，或者你自己有一台物理机跑着虚拟化。
这些机器走「**库存池**」模式：你提前录进后台、调优好、推到「待售」，
用户下单后从池子里分配一台。

---

## 7.1 两种模式的区别

| | 下单即开 | 库存池 |
|---|---------|-------|
| 机器什么时候存在 | 用户付款后才建 | 你提前准备好 |
| 空着的时候 | 不花钱 | 一直在花钱 |
| 交付速度 | 60–120 秒 | 立刻 |
| 能远程开机吗 | 能 | **不能**（见下） |
| 能真重装吗 | 能 | 看情况（见下） |
| 适合什么 | 谷歌云、Lightsail | 自己囤的机器、自建虚拟化 |

### 两条重要限制

**关机之后叫不醒。** 普通 VPS 没有带外管理，面板的「关机」是 SSH 进去执行
`poweroff`。关掉之后面板就再也连不上它了，只能到上游服务商的控制台去开机。
所以库存池的机器在用户控制台上**不显示「开机」按钮**，
关机按钮点之前会明确提示这一点。

**重装是「软重装」。** 没有虚拟化层就做不到真正的重装。面板做的是
「清空用户数据目录 + 重置凭据」，把机器恢复到一个干净基线，
但系统本身还是原来那个。**这一点必须写在套餐说明里**，
不然用户以为是全新系统，装过的东西没清干净会闹。

> 想要真正的开关机和重装，用 **Proxmox**（见 7.4）。
> 有虚拟化层就什么都能做了。

---

## 7.2 录一台机器进来

### 先准备好这些信息

| 需要 | 例子 |
|------|------|
| IP 地址 | `203.0.113.10` |
| SSH 端口 | `22` |
| 登录用户名 | `root` |
| 密码 **或** 私钥 | |
| 机器在哪 | `洛杉矶` |
| 几核几 G 多大盘 | 2 / 2048 / 40 |

### 建一个库存池套餐

先按 [第 5 章](05-上架第一个套餐.md) 建套餐，但这次：

| 字段 | 填什么 |
|------|--------|
| 履约方式 | **库存池** |
| 平台 | **自有机器（SSH）** |
| 用哪个云账号 | 不用填，SSH 驱动不需要 |

规格和价格照实填。卖点里**记得写清楚重装的限制**：

```
CN2 GIA 回程优化
BBR 已开启
现货即开，无需等待
重装为环境重置，非全新系统
```

### 录机器

后台 → 「**机器**」，按提示录入。录完之后系统会**立刻测一次连接**，
当场告诉你凭据填对没有。

---

## 7.3 状态流转

录进来的机器不是马上就能卖的，要走完这条链：

```
采购中 ──→ 优化中 ──→ 待售 ──→ 已锁定 ──→ 运行中
sourcing   optimizing   ready    reserved   running
```

| 状态 | 什么意思 | 你要做什么 |
|------|---------|-----------|
| **采购中** | 刚录进来，还没验过 | 点「测连接」确认能登进去 |
| **优化中** | 你正在调这台机器 | 装组件、调线路、做安全基线 |
| **待售** | 可以卖了 | 什么都不用做，等用户下单 |
| **已锁定** | 被某张订单占住了 | 等用户付款 |
| **运行中** | 已经交付给用户了 | — |

**只有「待售」的机器会被卖出去。** 前台商品卡上的「现货 N 台」
数的就是这个状态的机器数。

后台机器页上的流转按钮**只显示当前状态允许的下一步**，
不会把所有状态摆出来让你乱点 —— 乱改状态会让机器和订单对不上。

### 「优化中」这一步你该做什么

这是你的增值所在，也是你能卖得比上游贵的理由。常见的：

```bash
# 开 BBR（面板交付时也会自动做，但提前做了更稳）
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p

# 系统更新
apt update && apt upgrade -y

# 装常用组件
apt install -y curl wget vim htop
```

调完之后回后台把状态推到「**待售**」。

## 7.4 用 Proxmox 做真正的虚拟化

如果你有一台配置不错的物理机（或者一台大内存的独服），
装 Proxmox VE 之后可以切成很多台小虚拟机来卖。

**相比 SSH 驱动的好处：**

- 开关机走 API，关了还能远程开起来
- 重装是真的（删掉虚拟机从模板重新克隆）
- CPU / 内存 / 磁盘 / 流量数据 PVE 自己就记着，不用进机器里采

### 准备工作

**1. PVE 要能被面板访问到（8006 端口）**

PVE 在机房、面板在另一台服务器上的话，直接能通。
PVE 在你家里或者内网的话，用 WireGuard 或 Tailscale 把两边打通。

> ⚠️ **不要把 8006 端口裸露到公网上。** PVE 的管理界面暴露在公网
> 是很危险的，被爆破了整台物理机就没了。

**2. 建一个 API Token**

在 PVE 网页界面上：

1. 「数据中心」 → 「权限」 → 「API 令牌」
2. 点「添加」
3. 用户选 `root@pam`，令牌 ID 填 `panel`
4. **把「特权分离」的勾去掉**（否则要单独授权，麻烦）
5. 点「添加」

它会显示一个**密钥，只显示这一次**，复制下来。

完整的 Token ID 长这样：`root@pam!panel` —— 用户名 + 感叹号 + 令牌名。
少了感叹号面板会直接拦下来告诉你。

**3. 准备一个 cloud-init 模板机（要做真重装才需要）**

建一台虚拟机，装好系统和 `qemu-guest-agent`，然后转换成模板。
记下它的 VMID（比如 `9000`）。

```bash
# 在模板机里执行
apt install -y qemu-guest-agent
systemctl enable qemu-guest-agent
```

还要在 PVE 里给这台虚拟机的「选项」里启用 Guest Agent。

### 填进面板

后台 → 「**云账号**」 → 「**+ 自建 Proxmox VE**」

| 字段 | 填什么 |
|------|--------|
| PVE 地址 | `10.0.0.5` ← 只填 IP 或域名，不要带 `https://` 和端口 |
| 端口 | `8006` |
| 节点名 | `pve` ← 登录 PVE 后左侧树里那个名字 |
| API Token ID | `root@pam!panel` |
| Token 密钥 | 刚才复制的那串 |

点「添加并测试连接」。

> PVE 默认用的是自签证书，面板默认允许自签，不用额外处理。

### 建 Proxmox 套餐

| 字段 | 填什么 |
|------|--------|
| 履约方式 | 下单即开（配了模板）或 库存池（手工建好） |
| 平台 | 自建 Proxmox VE |
| 模板机 VMID | `9000` ← 配了才能真重装 |
| 存储 | `local-lvm` |
| 网桥 | `vmbr0` |

## 7.5 回收再上架

用户退订或者到期之后，库存机会回到「**优化中**」状态，不是直接「待售」。

**这是故意的。** 上一个用户在那台机器上装过什么、改过什么你并不知道，
直接转手卖给下一个人是有风险的。回收之后应该：

1. 重装或者彻底清理系统
2. 重新做一遍优化
3. 点「测连接」确认没问题
4. 再推到「待售」

---

## 到这一步你应该看到什么

- 后台「机器」页里有你录的机器，状态是「待售」
- 前台商品卡上显示「现货 N 台」，N 和你的待售数量对得上
- 点「测连接」返回「连接成功」，并显示系统版本、CPU 核数、内存

## 常见问题

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 测连接说「账号或密码不对」 | 凭据填错，或机器禁止 root 密码登录 | 检查凭据；机器上确认 `PermitRootLogin yes` |
| 测连接说「连接超时」 | IP 错了，或防火墙挡了 SSH 端口 | 检查 IP 和上游服务商的防火墙 |
| 测连接说「SSH 端口连不上」 | 端口号错了，或 sshd 没跑 | 确认端口；`systemctl status ssh` |
| 前台显示「暂时缺货」但我明明录了机器 | 机器不是「待售」状态 | 后台把状态推到待售 |
| 前台显示「暂时缺货」，机器也是待售 | 套餐的匹配规则和机器对不上 | 最简单的办法是建机器时直接绑定到那个套餐 |
| PVE 说「API Token 格式不对」 | 少了感叹号 | 应该是 `root@pam!panel` |
| PVE 说「权限不够」 | Token 没给够权限 | 在 PVE 权限里给它加 VM.Audit、VM.PowerMgmt、VM.Config.*、VM.Allocate、VM.Clone |
| PVE 建机时「拿不到 IP」 | 模板机没装 guest-agent | 在模板里装 `qemu-guest-agent` 并在选项里启用 |
