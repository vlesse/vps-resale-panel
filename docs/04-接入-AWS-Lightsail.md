# 第 4 章　接入 AWS Lightsail

这一章和上一章是一回事，只是换成 AWS。**没有 AWS 账号的话可以先跳过**，
面板不接 AWS 也能正常卖谷歌云的机器和你自己的机器。以后注册好了再回来填。

**全程大概 15 分钟**，全部在网页上点。

---

## 4.1 为什么用 Lightsail 而不是 EC2

AWS 有两条产品线能开虚拟机：

- **EC2**：按小时计费，配置项极多，流量单独算钱，账单很难预估
- **Lightsail**：按月固定价，含流量包，配置简单

**转售用 Lightsail 更合适**：固定价好算成本、好定价，也不容易因为流量超标
突然收到一张大账单。所以这套系统对接的是 Lightsail。

---

## 4.2 注册 AWS 账号

已经有的跳过这节。

打开 <https://aws.amazon.com>，点「创建 AWS 账户」。
注册要填信用卡（会预授权扣 1 美元验证，之后退回）和手机验证。

新账号有 12 个月免费套餐，但 Lightsail 的免费额度只有 3 个月的最小机型。

---

## 4.3 建一个专用的 IAM 用户

和谷歌云一样，**不要用你的主账号密钥**。建一个只有 Lightsail 权限的小号。

1. 登录 <https://console.aws.amazon.com>
2. 搜索框输入 `IAM`，点进「IAM」服务
3. 左侧菜单点「**用户**」
4. 点「**创建用户**」

**第一步：**

| 字段 | 填什么 |
|------|--------|
| 用户名 | `panel` |
| 提供用户对 AWS 管理控制台的访问权限 | **不要勾** |

> 不勾这个是因为面板只需要用密钥调 API，不需要这个小号能登网页控制台。
> 少一个入口少一分风险。

点「下一步」。

**第二步「设置权限」：**

1. 选「**直接附加策略**」
2. 搜索框输入 `Lightsail`
3. 勾选 「**AmazonLightsailFullAccess**」

⚠️ 别图省事勾 `AdministratorAccess`。那等于把整个 AWS 账号交出去，
一旦密钥泄露对方能删你所有东西。

点「下一步」 → 「**创建用户**」。

---

## 4.4 生成访问密钥

1. 在用户列表里**点你刚建的 `panel`**
2. 切到「**安全凭证**」标签页
3. 往下滚到「**访问密钥**」，点「**创建访问密钥**」
4. 用例选「**在 AWS 外部运行的应用程序**」
5. 勾选下面那个「我了解…」的确认框，点「下一步」
6. 描述随便填，点「**创建访问密钥**」

现在页面上会显示两个值：

```
访问密钥 ID       ：AKIAIOSFODNN7EXAMPLE
私有访问密钥      ：wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

> ⚠️ **「私有访问密钥」只显示这一次**，关掉页面就再也看不到了。
> 点「下载 .csv 文件」存起来，或者立刻复制到记事本。
> 弄丢了只能删掉重建一对。

---

## 4.5 确认区域

Lightsail 的机器要建在某个区域。常用的：

| 位置 | 区域代码 |
|------|---------|
| 新加坡 | `ap-southeast-1` |
| 东京 | `ap-northeast-1` |
| 首尔 | `ap-northeast-2` |
| 香港 | `ap-east-1` |
| 美国俄勒冈 | `us-west-2` |
| 美国弗吉尼亚 | `us-east-1` |

> ⚠️ **区域和可用区不是一回事**，这是最容易填错的地方：
>
> - **区域**：`ap-southeast-1` —— 填在云账号里
> - **可用区**：`ap-southeast-1a` —— 结尾多一个字母，填在**套餐**里
>
> 填反了面板会直接拦下来并告诉你。

---

## 4.6 填进面板

1. 后台 → 「**云账号**」 → 「**+ AWS Lightsail**」

| 字段 | 填什么 |
|------|--------|
| 账号备注名 | 随便，比如「AWS 主账号」 |
| Access Key ID | `AKIA` 开头那串 |
| Secret Access Key | 另外那串长的 |
| 区域 | 比如 `ap-southeast-1` |

2. 点「**添加并测试连接**」

---

## 到这一步你应该看到什么

绿色提示：

> **已添加，连接测试通过：连接成功**

云账号列表出现一条，脱敏摘要显示：

```
区域：Asia Pacific (Singapore)（ap-southeast-1）
密钥：AKIAIOSF********MPLE
```

## 报错对照表

| 提示 | 原因 | 怎么办 |
|------|------|--------|
| AWS 密钥无效 | ID 或 Secret 抄错了，或者密钥被停用了 | 回 IAM 确认，必要时重建一对 |
| Access Key ID 通常以 AKIA 开头，你可能把 Secret 和 ID 填反了 | 字面意思 | 两个框对调 |
| AWS 权限不够 | 4.3 第二步策略没附加上 | 回 IAM → 用户 → 添加权限 → AmazonLightsailFullAccess |
| 区域 xxx 不是有效的 Lightsail 区域 | 区域代码写错 | 照 4.5 的表填 |
| 区域填成可用区了 | 填了 `ap-southeast-1a` | 去掉结尾字母，改成 `ap-southeast-1` |
| AWS 账号还在初始化中 | 新注册的账号常见 | 等几分钟再试 |

## 建套餐时要填的参数

| 参数 | 填什么 | 注意 |
|------|--------|------|
| **可用区** | `ap-southeast-1a` | **结尾要带字母**，和区域不一样 |
| **套餐规格** | `small_3_0` | 见下表 |
| **系统镜像** | `debian_12` | 或 `ubuntu_22_04` |
| **固定公网 IP** | **勾上** | 理由和谷歌云一样 |

### 常用规格

| bundleId | 配置 | 含流量 | 月价（美元） |
|----------|------|--------|------------|
| `nano_3_0` | 2 vCPU / 0.5 GB / 20 GB | 1 TB | $5 |
| `micro_3_0` | 2 vCPU / 1 GB / 40 GB | 2 TB | $7 |
| `small_3_0` | 2 vCPU / 2 GB / 60 GB | 3 TB | $12 |
| `medium_3_0` | 2 vCPU / 4 GB / 80 GB | 4 TB | $24 |
| `large_3_0` | 2 vCPU / 8 GB / 160 GB | 5 TB | $44 |

> 价格因区域略有差异，以 <https://aws.amazon.com/lightsail/pricing/> 为准。
> 这些价格**已含流量包**，超出部分另收费，所以定价时要留余量。

### 关于登录用户名

Lightsail 的 Debian 镜像默认登录用户是 `admin`，Ubuntu 镜像是 `ubuntu`，
都不是 `root`。

**但你的用户拿到的仍然是 root** —— 面板在建机时会跑一段初始化脚本，
把 root 密码登录打开。这一步是自动的，你不用管。

---

## Lightsail 比谷歌云多给的两样东西

**监控曲线是现成的。** Lightsail 自带 CPU 和网络流量的历史数据，
面板直接问 AWS 要，不用往用户的机器里装任何监控软件。
所以 Lightsail 的机器在控制台上会显示一条 24 小时的 CPU 走势带，
谷歌云的机器没有这条（谷歌云的监控要另外配 Cloud Monitoring）。

**防火墙是 API 可控的。** 面板建机时会自动放行 22（SSH）、80（HTTP）、
443（HTTPS）三个端口。用户要开别的端口得自己去机器里配，
或者你在套餐的建机参数里加 `openPorts`。

---

## 同样要定期看账单

Lightsail 的机器列表在：<https://lightsail.aws.amazon.com/ls/webapp/home/instances>

**注意还要单独看一眼「静态 IP」标签页** —— 静态 IP 如果没绑在任何实例上，
AWS 会按小时收费。面板销毁机器时会一起释放，但如果销毁失败留下了孤儿 IP，
就会一直扣钱。后台总览页的「疑似还在计费的残留实例」会提醒你。

建议也设个账单告警：AWS 控制台搜 `Billing` → 「预算」 → 创建预算。
