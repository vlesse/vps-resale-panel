# 第 2 章　把面板装起来

这一章结束时，你在浏览器里打开 `https://panel.你的域名.com` 就能看到网站，
地址栏左边有个小锁（HTTPS 已生效），你也能用管理员账号登进后台。

**全程大概 20 分钟**，其中有 5 到 10 分钟是在等下载和编译。

> **为什么不用装 Node、MySQL、Nginx？**
> 因为这套系统用 Docker 打包好了。Docker 你可以理解成「一个能把整套环境
> 原样搬过来的箱子」—— 你不需要一个个去装那些软件，也不需要担心版本对不对。
> HTTPS 证书也是自动申请自动续期的，不用你管。

---

## 2.1 装 Docker

连上你的服务器（上一章那条 `ssh` 命令），然后**一整条**复制粘贴进去回车：

```bash
curl -fsSL https://get.docker.com | sh
```

这条要跑两三分钟。跑完之后验证一下：

```bash
docker --version && docker compose version
```

应该看到两行版本号，类似：

```
Docker version 27.4.1, build b9d17ea
Docker Compose version v2.32.1
```

> **如果 `curl` 说 command not found**：先 `apt install -y curl` 再重试。
>
> **如果 `docker compose version` 报错**（注意是两个词，中间有空格）：
> 你装的 Docker 太老了。执行 `apt install -y docker-compose-plugin`。

---

## 2.2 把代码下载下来

```bash
apt install -y git
git clone https://github.com/vlesse/vps-resale-panel.git /opt/panel
cd /opt/panel
```

> 之后每次要操作面板，都要先 `cd /opt/panel`。
> 记不住的话就记「面板在 /opt/panel」这一句。

---

## 2.3 填配置

这是唯一需要动脑的一步，一共填 8 个值。

先复制一份配置模板：

```bash
cp .env.example .env
```

### 先生成 4 个随机密码

这四个值是安全相关的，必须是**没人猜得到的随机字符串**。
一条命令生成好：

```bash
echo "MYSQL_ROOT_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=')"
echo "MYSQL_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=')"
echo "JWT_SECRET=$(openssl rand -base64 48 | tr -d '/+=')"
echo "CREDENTIALS_SECRET=$(openssl rand -base64 48 | tr -d '/+=')"
```

它会打印四行，类似：

```
MYSQL_ROOT_PASSWORD=k3Jd8sLpQr2mNvXcT9wZ
MYSQL_PASSWORD=Bn7yHt4uEi9oPa2sDf6g
JWT_SECRET=Xk9mQ2pL7vRt4nBc8yWs3jHd6fGa1zUe5oIr0tYq...
CREDENTIALS_SECRET=Zq4wEr7tYu2iOp9aSd5fGh8jKl3zXc6vBn1mQw...
```

**把这四行完整复制下来**，等下要粘进配置文件。

> ⚠️ **`CREDENTIALS_SECRET` 请另外单独存一份**（记事本、密码管理器都行）。
> 你的谷歌云密钥、AWS 密钥、每台卖出去的机器的 root 密码，都是用它加密后
> 存进数据库的。这个值一旦丢了或者改了，那些数据就永远解不开，
> 已经卖出去的机器面板再也管不了。

### 打开配置文件

```bash
nano .env
```

`nano` 是一个简单的文本编辑器。打开后你会看到一大堆带 `#` 的说明行
（`#` 开头的是注释，不用管）和一些 `名字=值` 的配置行。

**你要改的是这 8 行：**

```ini
PANEL_DOMAIN=panel.你的域名.com          ← 换成你的域名，不要带 https:// 不要带斜杠
ACME_EMAIL=you@example.com              ← 换成你的邮箱
SITE_NAME=RenrenYings Cloud             ← 网站名字，随便改

MYSQL_ROOT_PASSWORD=                     ← 粘贴刚才生成的第 1 个
MYSQL_PASSWORD=                          ← 粘贴第 2 个
JWT_SECRET=                              ← 粘贴第 3 个
CREDENTIALS_SECRET=                      ← 粘贴第 4 个

ADMIN_EMAIL=admin@你的域名.com            ← 你自己的登录邮箱
ADMIN_PASSWORD=                          ← 你自己想一个，至少 8 位
```

**nano 的操作方法：**

| 想干什么 | 怎么做 |
|---------|-------|
| 移动光标 | 方向键 |
| 粘贴 | 鼠标右键（PowerShell 里）或 Ctrl+Shift+V |
| 保存 | Ctrl + O，然后回车 |
| 退出 | Ctrl + X |
| 撤销 | Ctrl + U |

改完按 `Ctrl+O`、回车、`Ctrl+X` 退出。

### 检查一下有没有漏填

```bash
grep -E '^(PANEL_DOMAIN|ACME_EMAIL|MYSQL_ROOT_PASSWORD|MYSQL_PASSWORD|JWT_SECRET|CREDENTIALS_SECRET|ADMIN_EMAIL|ADMIN_PASSWORD)=' .env
```

打出来的 8 行，**每一行等号后面都必须有内容**。
哪一行是空的就再 `nano .env` 回去补上。

## 2.4 启动

```bash
docker compose up -d
```

**第一次跑要 5 到 10 分钟**，因为它要下载几个镜像并且编译前后端代码。
屏幕上会滚很多字，是正常的。

跑完之后看看状态：

```bash
docker compose ps
```

应该看到 5 个服务，STATUS 那一列都是 `Up`：

```
NAME                SERVICE   STATUS
panel-api-1         api       Up (healthy)
panel-caddy-1       caddy     Up
panel-mysql-1       mysql     Up (healthy)
panel-redis-1       redis     Up (healthy)
panel-web-1         web       Up
```

> `mysql` 和 `api` 后面括号里从 `starting` 变成 `healthy` 需要一两分钟，
> 耐心等一下再看一次。

---

## 2.5 打开网站

浏览器输入：

```
https://panel.你的域名.com
```

**注意是 `https`，不是 `http`。**

第一次打开可能要等 10 到 30 秒 —— Caddy 正在向 Let's Encrypt 申请证书。
等它转完，你应该看到一个深色的、像机架设备一样的页面，上面写着
「云服务器，交付到分钟」。

地址栏左边应该有一个**小锁图标**，点开显示「连接是安全的」。

---

## 2.6 登进后台

点右上角「登录」，用你在 `.env` 里填的：

- 邮箱：`ADMIN_EMAIL` 的值
- 密码：`ADMIN_PASSWORD` 的值
- 验证码：照着图片输

登录成功后，导航栏会多出「后台」两个字，点进去就是管理界面。

## 到这一步你应该看到什么

**1. 五个容器都在跑**

```bash
cd /opt/panel && docker compose ps
```

五行都是 `Up`。

**2. 后端是健康的**

```bash
curl -s https://panel.你的域名.com/api/health
```

应该返回：

```json
{"status":"ok","database":"ok","latencyMs":3,"time":"2026-..."}
```

`"status":"ok"` 和 `"database":"ok"` 两个都要对。

**3. 浏览器能打开，有小锁**

**4. 能用管理员账号登进后台**

## 没成功？按现象查

### 浏览器打不开，一直转圈

**先确认 DNS 解析对不对**（在你自己电脑上）：

```bash
nslookup panel.你的域名.com
```

IP 必须是你服务器的 IP。不对的话回第 1 章重做解析，等 10 分钟。

**再确认 80/443 端口有没有被防火墙挡住**。到你服务商后台找
「安全组」或「防火墙规则」，确认 80 和 443 是放行的。

### 浏览器说「不安全」或者证书错误

证书没申请下来。看 Caddy 的日志：

```bash
cd /opt/panel && docker compose logs caddy --tail 40
```

| 日志里出现 | 意思 | 怎么办 |
|-----------|------|--------|
| `no such host` / `DNS problem` | 域名没解析到这台机器 | 回第 1 章检查解析 |
| `connection refused` on port 80 | 80 端口被挡了 | 到服务商后台放行 80 |
| `too many certificates` | 你反复重启太多次，触发了 Let's Encrypt 的频率限制 | 等一小时再试。这期间可以先编辑 `deploy/Caddyfile` 打开 `acme_ca` 那行用测试证书 |

### `docker compose ps` 里有服务不是 Up

看那个服务的日志。比如 api 挂了：

```bash
docker compose logs api --tail 50
```

| 日志里出现 | 意思 | 怎么办 |
|-----------|------|--------|
| `CREDENTIALS_SECRET 至少要 32 个字符` | 那个值填短了或者没填 | `nano .env` 补上，然后 `docker compose up -d` |
| `Can't connect to MySQL` | 数据库还没起来 | 等一分钟。一直这样的话看 `docker compose logs mysql` |
| `Access denied for user 'vps'` | `.env` 改过 MySQL 密码但数据库还是老的 | 见下面「想重来一次」 |

### 想彻底重来一次

⚠️ **这会删掉所有数据**（用户、订单、机器记录全没）。只在还没正式用的时候做：

```bash
cd /opt/panel
docker compose down -v      # -v 表示连数据卷一起删
docker compose up -d
```

## 以后常用的几条命令

```bash
cd /opt/panel               # 所有命令都要先进这个目录

docker compose ps           # 看各个服务活着没有
docker compose logs -f api  # 实时看后端日志（Ctrl+C 退出）
docker compose restart api  # 重启后端
docker compose down         # 全部停掉（数据保留）
docker compose up -d        # 全部启动
```

**改完 `.env` 之后要让它生效**：

```bash
docker compose up -d        # 会自动重建受影响的容器
```

## 顺便说一下防刷单闸门

`.env` 里还有三个值，**默认值是安全的，但你应该知道它们在管什么**：

```ini
MAX_ACTIVE_SERVICES_PER_USER=5    # 单个用户最多同时持有 5 台机器
MAX_DAILY_PROVISION=50            # 全平台每天最多自动建 50 台
ORDER_EXPIRE_MINUTES=30           # 未付款订单 30 分钟后自动取消
```

「下单即开」的套餐，用户每买一台你的云账单就多一台。
没有这些闸门，一个人写个脚本刷单就能把你的账单刷爆。
**生意做大了再往上调，别一上来就关掉。**
