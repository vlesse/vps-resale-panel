# 第 11 章　三个月换一次谷歌云货源

你的货源是有期限的：一个谷歌云账号能用大约三个月，到期就得换一个新的重新对接。
这一章是**每三个月要照着做一遍的操作单**，从新账号开卡一直到旧账号清场。

第 3 章讲的是「第一次怎么接谷歌云」。这一章不重复那些，只讲**换的时候多出来的那些事**——
面板这边要改什么、已经卖出去的机器怎么处理、旧账号什么时候才能动。

> **全程大概 40 分钟**，其中等谷歌云开 API 和批配额可能要额外等几小时到一两天。
> **务必提前一周做**，别等到期当天。

---

## 11.1 时间线：什么时候开始做

| 距离到期 | 做什么 |
|---------|-------|
| **7 天** | 开新账号、走完 11.3 全部步骤、在面板里加好新云账号并测试通过 |
| **5 天** | 用新账号手工下一单测试机，确认能建能连能删（11.5） |
| **3 天** | 把套餐切到新账号（11.6），发公告提醒用户备份 |
| **到期当天** | 旧账号停用（**不是删除**），确认没有新单落到旧账号上 |
| **到期后 3 天** | 旧项目清场，确认不再产生费用（11.8） |

最关键的是**「切套餐」要在旧账号还活着的时候做完**。
切完之后新下的单去新账号，老机器还在旧账号上跑到最后一天 —— 两边并行几天，
比到期当天手忙脚乱强得多。

---

## 11.2 先看清楚现在用的是哪个

登录面板 → **后台** → **云账号**。

你会看到已有的谷歌云账号，卡片上有脱敏摘要：

```
项目：vps-panel-472913
服务账号：panel@vps-panel-472913.iam.gserviceaccount.com
```

**把这个项目 ID 抄下来**，第 11.8 节清场时要用它去谷歌云里核对。

再去 **后台 → 套餐**，把用谷歌云的套餐列一遍，记下有几个 ——
第 11.6 节要一个一个改，漏掉一个那个套餐就会一直往死账号上建机。

---

## 11.3 新账号那边：从零到拿到 JSON

这一节和第 3 章基本一样，但有**三处新账号才会遇到的坑**，用 ⚠️ 标出来了。

### 第一步：注册并绑卡

1. 用新的谷歌账号打开 <https://console.cloud.google.com>
2. 首次进入会让你同意条款、选国家，照着点
3. 点「**免费开始使用**」，按提示填信用卡

> ⚠️ **同一张信用卡在谷歌云上只能领一次免费额度。**
> 第二次用同一张卡开新账号，卡能绑上、账号能用，但**不会再给试用额度**，
> 直接按实际用量扣钱。要留试用额度就得换卡。

### 第二步：建项目

1. 页面**最上方中间**的项目选择器（显示当前项目名的下拉框）
2. 弹窗右上角「**新建项目**」
3. 项目名填个带日期的，比如 `vps-panel-2609` —— 三个月换一次，
   不带日期的话过两轮你自己都分不清哪个是哪个
4. 点「创建」，等十几秒

**在项目选择器弹窗的「ID」那一列把项目 ID 抄下来**（形如 `vps-panel-2609-472913`）。
项目 ID 和项目名不是一回事，后面填面板要用 ID。

> 找不到某个页面时，用控制台**最上方的搜索框**直接搜名字，比翻菜单快得多。
> 下面每一步我都给了菜单路径，但谷歌云改版很勤，搜索框永远是对的。

### 第三步：确认结算账号绑到了这个项目上

左上角三横线菜单 → 「**结算**」。

如果显示「此项目没有结算账号」，点「**关联结算账号**」，选你刚开的那个。

> ⚠️ **新建的项目不会自动继承结算账号。** 这一步漏了的话，前面全对，
> 到建机那一步才报错，而且报的是配额相关的错，看不出是没绑结算。

### 第四步：启用 Compute Engine API

菜单 → 「**API 和服务**」 → 「**库**」 → 搜 `Compute Engine API` → 点进去 → 「**启用**」。

要等两三分钟，等按钮变成「管理」就好了。

### 第五步：看一眼配额 ⚠️

菜单 → 「**IAM 和管理**」 → 「**配额和系统限制**」。

在筛选框里搜 `CPUs`，找到你要卖的那个区域（比如 `asia-east2` 是香港）。

> ⚠️ **这是新账号最容易翻车的地方。** 试用账号的 CPU 配额通常被卡在很低的数
> （常见是全部区域加起来 8 个，有的新账号某些区域是 0）。
> 配额是 0 或者不够的话，面板建机会失败，报
> `Quota 'CPUS' exceeded` 之类的话 —— 而前面每一步测试都是通过的。
>
> 配额不够就点那一行的「**编辑配额**」申请提额。谷歌一般几小时到两天批。
> **试用期间有些账号根本不让提额**，那就只能先升级成正式付费账号
> （试用额度不会因此作废，还能继续用完）。
>
> **这一步必须在开卖之前做完。** 等用户下了单才发现配额不够，
> 那是一边退款一边赔笑脸。

顺便算一下：你打算同时在线多少台机器 × 每台几核 = 需要多少 CPU 配额，
再留 20% 余量。

### 第六步：建服务账号并给两个角色

菜单 → 「**IAM 和管理**」 → 「**服务账号**」 → 顶部「**+ 创建服务账号**」。

| 字段 | 填什么 |
|------|--------|
| 服务账号名称 | `panel` |
| 服务账号 ID | 自动填成 `panel`，不用改 |
| 说明 | 随便，比如「转售面板用」 |

点「**创建并继续**」。

**第二步「授予对项目的访问权限」要加两个角色**，一个都不能少：

1. 点「选择角色」，搜 `Compute 管理员`（英文 `Compute Admin`）→ 选
   **Compute 管理员** `roles/compute.admin`
2. 点「**+ 添加其他角色**」，搜 `服务账号用户`（英文 `Service Account User`）→ 选
   **服务账号用户** `roles/iam.serviceAccountUser`

点「继续」，第三步不填，直接「**完成**」。

> ⚠️ **别选「Compute 实例管理员 (v1)」**。名字看着更贴切、权限更小，
> 但它不包含 `compute.addresses.create`，也就是**不能预留静态 IP**。
> 用它建机会一路走到分配固定 IP 那步才失败。
> 固定 IP 不是可选项 —— 谷歌云没有重装 API，面板的重装是删了重建，
> 没固定 IP 用户每重装一次地址就换一次。

### 第七步：下载 JSON 密钥

1. 回服务账号列表，**点 `panel` 这个名字**（不是右边的三个点）
2. 上方标签页切到「**密钥**」
3. 「**添加密钥**」 → 「**创建新密钥**」 → 类型选 **JSON** → 「创建」

浏览器自动下载一个 `.json`，文件名形如 `vps-panel-2609-472913-a1b2c3.json`。

> ⚠️ 这个文件**只能下载这一次**，关掉就没了，弄丢只能再建一把新的。
> 它等于你谷歌云的钥匙，别发群里、别提交到 GitHub。
>
> 建议存到密码管理器里，并**在文件名上标好是哪一轮的**，
> 三个月后清场时你要能分清哪把钥匙对应哪个项目。

## 11.4 面板这边：把新账号加进去

**后台** → **云账号** → 「**+ 谷歌云 Compute Engine**」。

| 字段 | 填什么 |
|------|--------|
| 账号备注名 | **带上日期**，比如「谷歌云 2609（到期 2609-12）」 |
| 项目 ID | 11.3 第二步抄的那串 |
| 服务账号密钥 | 用**记事本**打开 JSON，`Ctrl+A` 全选、`Ctrl+C`，粘进来 |

> ⚠️ 从第一个 `{` 粘到最后一个 `}`，一个字符都不能少。
> **别用 Word 或者带格式的编辑器打开** —— 它们会动引号和换行，
> 改过的密钥签名对不上，面板会提示「密钥签名校验没过」。

备注名带日期这件事看着无所谓，但你很快会有两三个「谷歌云」并排躺着，
切套餐的时候选错一个，机器就建到快死的账号上去了。

点「**添加并测试连接**」，看到绿色的「连接测试通过」才算完。

---

## 11.5 先自己买一台试试

**别跳过这一步。** 连接测试只证明凭据能用，证明不了配额够、区域对、镜像存在。

1. 临时建一个只有你自己知道的套餐，或者直接把某个现有套餐改到新账号（下一节的做法）
2. 用你自己的账号下一单，走完整流程
3. 确认：能建出来、能 SSH 连上、能在控制台开关机、能重装、能销毁

销毁那一步也要做 —— 它验的是权限里最容易缺的那块（删实例 + 释放静态 IP）。

---

## 11.6 把套餐切到新账号

**后台** → **套餐** → 逐个点「编辑」。

在「**用哪个云账号**」那个下拉框里，选你刚加的新账号（认备注名里的日期），保存。

**11.2 里数过有几个谷歌云套餐，这里就要改几个。** 漏一个，那个套餐会一直往
即将过期的账号上建机，而且不会有任何报错 —— 直到某天建机开始失败。

> 改套餐**只影响以后新建的机器**。已经卖出去在跑的机器仍然挂在旧账号上，
> 面板照样能查状态、开关机、销毁它们 —— 这是对的，它们本来就在旧项目里。

---

## 11.7 已经卖出去的机器怎么办

**说清楚一件事：老机器迁不过去。**

谷歌云的实例不能跨项目搬。面板的「重装」也不行 —— 重装是在**机器所在的那个项目里**
删了重建，它救不了一个即将消失的项目。

所以现实是：**旧账号一到期，上面所有机器连同数据一起没了。**

这就是为什么：

1. **售卖页和弹窗必须写明「最长两个月多、最短一个月就会到期重置」**，
   让用户自己做备份。面板首页的弹窗已经在说这件事了。
2. **到期前至少 7 天再单独提醒一次**。后台 → 用户，导出还在跑的服务对应的邮箱，
   群发一封「X 月 X 日重置，请备份」。
3. 到期后用户要继续用，就是**重新下一单**，在新账号上开一台新的。

如果你想给老客户省事，可以在到期前给他们发个优惠，让他们提前在新账号上开好新机，
自己把数据倒过去，两边并行两天。这比事后解释「数据没了」代价小得多。

> 别自作主张替用户搬数据 —— 你没有他们的密码，也不该有。
> 你能做的是**给足时间和提醒**。

## 11.8 旧账号清场

### 先停用，别删

到期当天，**后台 → 云账号 → 旧账号 → 点「停用」**。

> **千万别点「删除」。** 停用只是不再往它上面建新机；
> 删除之后面板就再也够不到那些老机器了 —— 查不了状态、关不了机、
> 更销毁不了，它们会在旧项目里一直挂着（有可能还在扣钱）。
>
> 等旧项目里确认一台机器都不剩了，再回来删这条记录。

### 去谷歌云确认没有残留在扣钱的东西

用**旧账号**登录 <https://console.cloud.google.com>，
确认页面顶部选的是 11.2 里抄下来的那个旧项目，然后逐项看：

| 看哪里 | 菜单路径 | 该是什么样 |
|-------|---------|-----------|
| 虚拟机 | Compute Engine → **虚拟机实例** | 空 |
| 静态 IP | VPC 网络 → **IP 地址** | 空。**留着不用的静态 IP 照样每月扣钱** |
| 磁盘 | Compute Engine → **磁盘** | 空。删实例时没勾「一并删除启动磁盘」就会剩下 |
| 快照 | Compute Engine → **快照** | 空 |
| 映像 | Compute Engine → **映像** | 空（除非你自己做过自定义镜像） |

> 最容易漏的是**静态 IP 和孤儿磁盘**。它们不显示在「虚拟机实例」里，
> 但每个月都在扣钱，金额不大，很容易几轮之后才发现。

### 最后关掉计费

确认全空之后：菜单 → 「**结算**」 → 「**账号管理**」 → 「**关闭结算账号**」，
或者直接把项目「**关停**」（菜单 → IAM 和管理 → 设置 → 关停）。

项目关停后有 30 天缓冲期，期间还能恢复，30 天后彻底删除。

## 11.9 每次照着打勾

```
新账号那边
  [ ] 注册并绑卡（注意同卡不重复给额度）
  [ ] 建项目，抄下项目 ID
  [ ] 确认结算账号已关联到这个项目
  [ ] 启用 Compute Engine API
  [ ] 查 CPU 配额，不够就提前申请提额     ← 最容易翻车
  [ ] 建服务账号，加满两个角色
  [ ] 下载 JSON 密钥，存好并标注轮次

面板这边
  [ ] 添加云账号，备注名带日期，测试连接通过
  [ ] 自己下一单，走完建机 → 连上 → 重装 → 销毁
  [ ] 逐个套餐改「用哪个云账号」，数量和 11.2 数的对得上
  [ ] 发到期公告，提醒用户备份

旧账号那边
  [ ] 云账号点「停用」（不是删除）
  [ ] 虚拟机 / 静态 IP / 磁盘 / 快照 / 映像 逐项确认为空
  [ ] 关闭结算或关停项目
  [ ] 确认全空后，再回面板把旧云账号记录删掉
```

## 报错对照表（换账号时特有的）

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 连接测试过了，但建机报 `Quota 'CPUS' exceeded` | 新账号配额没提 | 回 11.3 第五步申请提额 |
| 建机报 `Permission denied on service account` | 只加了 Compute 管理员，漏了服务账号用户 | 回 IAM 补第二个角色 |
| 建机走到分配固定 IP 才失败 | 角色选成了「Compute 实例管理员 (v1)」 | 换成「Compute 管理员」 |
| 建机报没有结算账号 | 新项目没关联结算 | 回 11.3 第三步 |
| 某个套餐还在往旧账号建机 | 11.6 漏改了这一个 | 后台 → 套餐 → 编辑 → 改「用哪个云账号」 |
| 旧机器点重装报权限不足 | 旧项目已经关停或密钥已删 | 已经没救了，只能销毁记录，让用户重新下单 |
| 旧账号删了之后老机器全变「异常」 | 云账号记录被删，面板够不到那些实例了 | 只能去谷歌云控制台手工删实例，再在面板里把机器标记为已清理 |

## 顺带一提：不想每三个月折腾一次的话

这套流程本身是可以并行的 —— 面板支持**同时挂多个云账号**，
不同套餐指向不同账号。所以你也可以：

- **错开开卡**：不要一次开一个用三个月，而是每月开一个、每个卖两个月，
  这样任何时刻都有两个账号在跑，到期时受影响的只有一半用户。
- **留一个正式付费账号打底**，把「不能中断」的客户放在上面（价格相应高一些），
  试用账号只承接明确接受「一两个月会重置」的便宜档。

第二种做法能让你多卖一档产品，而且投诉会明显减少 ——
现在所有客户共担这个风险，愿意多花钱买稳定的那部分人其实是被浪费掉的。
