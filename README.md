# RenrenYings 云服务器转售面板

一套自己卖云服务器的完整系统。用户在你的网站上下单付款，系统自动去谷歌云或
AWS 建一台机器，把 IP 和密码交给他；他能在你的网站上直接开关机、重启、
改密码、重装系统 —— 和在云厂商自己的控制台里操作是同一套动作。

你也可以把自己手上已有的机器放进来卖，那些机器走「库存池」模式：
你提前录进后台调优好，用户下单后从池子里分配一台。

---

## 这套系统能做什么

**对你（运营者）**

- 把谷歌云、AWS Lightsail 的机器包装成自己的套餐卖，赚差价
- 也能卖自己手上的机器（自建 Proxmox 虚拟机，或任何能 SSH 进去的服务器）
- 后台看订单、看收入、管机器、管用户
- 自动到期挂起，自动清理超时未付款的订单
- 有一个「疑似还在计费的残留实例」告警 —— 防止建机失败留下的机器偷偷烧钱

**对你的用户**

- 挑机型、下单、付款，一分钟左右拿到机器
- 自助开关机、重启、重置密码、重装系统，不用发工单等人
- 看机器的实时 CPU、内存、磁盘、流量
- 到期前自助续费

## 几件必须先知道的事

**这套系统会花你的真钱。** 「下单即开」的套餐，用户每买一台，
就会在你的云账号上真的建出一台机器并开始按小时计费。所以：

- 一定要在 `.env` 里设好防刷单闸门（第 2 章会讲），别关掉它们
- 定价一定要高于你的云成本，否则卖得越多亏得越多
- 后台总览页上那个「疑似还在计费的残留实例」，看到数字不是 0 就要处理

**谷歌云和 AWS 都没有「重装系统」这个功能。** 它们的控制台上也没这个按钮。
所谓重装的真实做法是「删掉旧的，用同样的参数建一个新的」。
所以你的套餐**一定要开「固定公网 IP」**，否则用户每重装一次 IP 就变一次 ——
这是转售最容易挨投诉的地方。系统在你建套餐时会强制你确认这一项。

**凭据加密密钥不能改。** `.env` 里的 `CREDENTIALS_SECRET` 一旦开始用就绝对不能改。
你的云账号密钥、每台机器的密码都是用它加密后存进数据库的。
改了之后所有历史数据都解不开，已经卖出去的机器面板就永远管不了了。
填完请另外备份一份。

## 技术构成（懂技术的看这段，不懂可以跳过）

```
浏览器
  │
  ▼
Caddy ──────── 自动申请和续期 HTTPS 证书
  ├── /api/*  → NestJS 后端（Node 22）
  └── 其余     → Next.js 前端（React 19）
                     │
       ┌─────────────┼──────────────┐
       ▼             ▼              ▼
   MySQL 8       Redis          驱动层
   业务数据       建机任务队列    ├── 谷歌云 Compute Engine
                                ├── AWS Lightsail
                                ├── SSH（自有机器）
                                └── Proxmox VE
```

四个驱动实现同一个接口，上层代码不知道机器是哪家云的。
要接第五家云厂商，写一个实现 `VpsProvider` 接口的类、在注册表里加一行即可，
上层一行都不用改。接口定义见 [`apps/api/src/providers/provider.types.ts`](apps/api/src/providers/provider.types.ts)。

- **后端** NestJS 11 + Prisma 6 + MySQL 8 + BullMQ（Redis）
- **前端** Next.js 15 + React 19，纯客户端渲染，令牌存 localStorage
- **部署** Docker Compose，五个容器：mysql / redis / api / web / caddy

### 本地开发

```bash
# 起数据库和队列
docker compose up -d mysql redis

# 后端（会自动杀掉占端口的旧进程再启动）
./dev-restart.sh

# 前端
./dev-web.sh
```

后端在 3010，前端在 3011。**不要在 `next dev` 跑着的时候执行 `next build`** ——
生产构建会覆盖 `.next/` 目录，把开发用的资源全删掉，
结果是页面看着正常但所有数据都是空的，非常难查。

改完代码跑一下自检：

```bash
cd apps/api && npx ts-node --compiler-options '{"module":"commonjs"}' scripts/selfcheck.ts
```

它检查的是那些「写错了不会立刻报错、但会在生产上悄悄坏掉」的地方：
SSH 公钥的二进制编码、凭据加解密、密码里的特殊字符会不会把 shell 搞断、
支付签名的算法、机器状态采集的解析。
